Privacy Policy

API Mock Manager browser extension · Effective November 21, 2026

API Mock Manager ("the extension") is a developer tool that returns mock responses for fetch and XMLHttpRequest calls made by web pages. It was built by Majid Ali, an independent developer. This policy explains what data the extension handles and where that data goes.

Summary

  • No data collection. The extension does not collect, transmit, sell, or share any personal data.
  • No servers. The extension has no backend, account system, analytics, telemetry, or advertising.
  • Local only. Everything you create stays in your browser on your device.

Data stored on your device

  • Collections and API mocks (names, URLs or URL patterns, HTTP methods, status codes, headers, request and response payloads, delays). These are stored in your browser's IndexedDB.
  • UI preferences and unsaved form drafts (for example, your theme choice). These are stored in the extension's localStorage.
  • Settings: the global on/off switch and, while recording, which collection and tab are being recorded. These are stored in chrome.storage.local.
  • Interception counts and the request log: how many times each mock was used, plus the method, URL, status and mock name of the last 200 mocked requests. These are kept in memory only and are cleared when the browser or extension restarts, or when you click "Clear" in the log.
  • Recorded responses, only if you start recording (see below). They are saved as mocks in IndexedDB.

You can delete this data at any time. Delete collections in the extension, use "Clear Cache" in the info panel, or remove the extension. Removing the extension deletes all of its stored data.

How web pages are affected

To intercept requests, the extension runs a script on the web pages you visit. When a page makes a network request, the extension compares the request with your enabled mocks (URL, method and, if you set them, query parameters or body), entirely inside your browser. Request and page contents are never sent anywhere. Unless you start recording, the only request details kept are the memory-only log entries for requests a mock answered.

Each collection can be limited to specific sites (for example localhost:3000 or *.example.com). A page receives only the mocks from collections that apply to it. Each mock sent includes only the fields needed to answer a request: URL pattern, method, conditions, status, headers, delay, behavior, and response body. Labels and descriptions never reach web pages. A request payload is sent only when you have turned on body matching for that mock. Collections with no sites set apply to all sites, and the popup marks them with a 🌐 badge.

Mocks travel from the extension to the page over a private channel that is set up before any of the page's own scripts run. The page's scripts cannot listen in on it. Even so, the response you configure is, by design, handed to the page as the reply to its request. Do not put real passwords, tokens, API keys, or personal data in mock payloads.

Recording

Recording only happens when you choose "Record from current tab" for a collection. While it is on, real responses (JSON, text or XML, up to 512 KB) that the page in that one tab receives are saved as disabled mocks in that collection, together with the request body that produced each one. If the collection is limited to certain sites, only those sites are recorded. Recording stops when you stop it or close the tab, and the toolbar badge shows REC while it is on. Recorded data stays on your device like any other mock. It may include personal data returned by the site, so review it before you export or share it.

Permissions

  • Content scripts on all sites (<all_urls>): needed so mocks can apply to whatever site you are developing or testing. You can limit each collection to the sites you choose. Pages that no enabled collection applies to receive no mock data.
  • Storage (storage): saves the on/off switch and recording state on your device.
  • The extension requests no other permissions. It does not read your browsing history, cookies, bookmarks, or the contents of your tabs.

Import and export

Exported files are created on your device and saved wherever you choose. Imported files are read locally. The extension never uploads them. Before you share an export, check that it contains nothing sensitive.

Third-party links

The info panel links to the developer's portfolio and GitHub. Opening those links takes you to external websites, which have their own privacy practices.

Chrome Web Store Limited Use

The extension does not collect user data. Its use of information therefore complies with the Chrome Web Store User Data Policy, including the Limited Use requirements.

Children

The extension is a developer tool. It is not directed at children and collects no data from anyone.

Changes to this policy

If this policy changes, the updated version will be published with the extension and in its source repository, with a new effective date.
